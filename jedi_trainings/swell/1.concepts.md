## What is SWELL?

SWELL is a workflow layer that manages **tasks** such as creating the run directory for each assimilation window, copying or linking relevant observations, backgrounds, or any other input files in the run directory, building JEDI input YAML files, running JEDI executble, and handling JEDI or model output files.

SWELL uses Cylc to determine the depencies between different tasks. The order of different **tasks** is usually defined in a file called `flow.cylc`. 


### Tasks

SWELL tasks are Python classes that live under [`src/swell/tasks`](https://github.com/GEOS-ESM/swell/tree/develop/src/swell/tasks). 

| Task | Does |
|------|------|
| `CloneJedi` | Clone the JEDI source repos |
| `BuildJediByLinking` | Try to symlink an existing build (fast path) |
| `BuildJedi` | Compile JEDI (slow path, only if linking failed) |
| `GetBackground` | `r2d2.fetch` the forecast files this cycle needs |
| `GetObservations` | `r2d2.fetch` the obs files|
| `RenderJediObservations` | Fill in the obs-space YAML templates |
| `StageJedi` | Put static files (coefficients, geometry) in place |
| `RunJediHofxExecutable` | Actually run JEDI under SLURM |
| `EvaObservations` | Generate diagnostic plots and stats |
| `SaveObsDiags` | `r2d2.store` the feedback files |
| `CleanCycle` | Delete the large intermediates |

You can run any of them by hand:

```bash
swell task GetObservations $config -d $datetime -m geos_cf
```

### Suites, suite configs, experiments

A **Suite** directory lives under [`src/swell/suites/`](https://github.com/GEOS-ESM/swell/tree/develop/src/swell/suites). In this folder you will find a `flow.cylc` (the task depency graph), `suite_config.py` (list of suite configuraitons), and EVA folder (holds EVA YAMLs for plotting).

 In `suite_config.py` multiple configuration can be listed. For example in [`r2d2_ingest` suite](https://github.com/GEOS-ESM/swell/blob/develop/src/swell/suites/r2d2_ingest/suite_config.py):

 ```
 src/swell/suites/r2d2_ingest/           ← the suite (one flow.cylc)
├── flow.cylc
└── suite_config.py
    ├── r2d2_ingest                     ← base config, others inherit from it
    ├── ingest_obs_marine               ← specific config for marine obs
    ├── ingest_obs_cf                   ← specific config for CF obs
    └── ingest_background_cf            ← specifc config for CF background (jdi collection)
```


In this example, `ingest_obs_cf` and `ingest_background_cf` are not separate suites. They are two configurations of `r2d2_ingest`, and they select different "branches" of the same `flow.cylc` via flags (`download_convert_pipeline`, `ingest_background_pipeline`). 

An **experiment** is what `swell create` command produces which is a directory on disk with a rendered `experiment.yaml`, a copy of the configuration tree, and a Cylc suite ready to launch. 

You can create an `ingest_obs_cf` experiment by running:

```bash
swell create ingest_obs_cf
```

Running `swell create` withouth additional word will print out all the available suites.

Here's an example of what is in a **experiment directory**:

```
<experiment_root>/<experiment_id>/
├── configuration/
│   └── jedi/
│       └── interfaces/
│           └── geos_cf/
│               ├── download_observations/    ← where to get raw granules
│               ├── convert_observations/     ← how to run the IODA converter
│               ├── ingest_observations/      ← what to store in R2D2
│               ├── observations/             ← JEDI obs-space YAML templates
│               └── model/
├── jedi_bundle/
└── <experiment_id>-suite/
    ├── flow.cylc
    ├── experiment.yaml    ← the rendered answers
    └── modules            ← source this to run tasks by hand
```

Note that if you want to make changes in any of the files under `configuration` directory after running `swell create` you need to change the files under `<experiment_root>/<experiment_id>/configuration/` and not under SWELL source code.
