# Getting Started

## Installing Swell

Swell documentation describes these steps in much more details. Here we provide an high-level summary of the steps needed to install and run Swell.


- Start by loading modules needed by Swell and JEDI by using:

```bash
source /discover/nobackup/projects/gmao/advda/swell/jedi_modules/spackstack_1.9_intel_bundle
```

- Next, clone the Swell code repository. It's recommended to work in $NOBACKUP

```bash
cd $NOBACKUP
mkdir swell-project
cd swell-project
git clone https://github.com/GEOS-ESM/swell.git swell-develop
```
- It's best to create a virtual Python environment and install Swell in that environment.

```bash
uv venv
source .venv/bin/activate 
# make sure your environment is active before instalation
uv pip install -e .
```

## Setting up R2D2 credentials

For GEOS-CF experiments we rely on R2D2 for fetching and storing experiment input and output files. Each user will have their own R2D2 credentials which need to be set as environment variable. 


```bash
export R2D2_USER="your_r2d2_username"
export R2D2_API_KEY="your_r2d2_apikey"

#WHICH SERVER TO USE?
export R2D2_HOST=discover-gmao
export R2D2_COMPILER=intel

export R2D2_HOST=discover
export R2D2_COMPILER=intel
export R2D2_USER=<>
export R2D2_API_KEY=<>
export R2D2_SERVER_HOST="http://13.217.72.149"
export R2D2_SERVER_PORT=8080
```


## Running a simple case

After installing Swell and setting up the R2D2 credentials, you can start running a simple `hofx_cf` experiment.
In your activated Python environment run:

```bash
swell create hofx_cf
```

With this command the `hofx_cf` experiment will be created and the directories are set in `/discover/nobackup/${USER}/SwellExperiments`. In this directory you will see two subdirectories `swell-hofx_cf` and `cylc_run`. The hofx_cf experiment is installed in `swell-hofx_cf`. `cylc_run` will hold each task's log file when the experiment is launched. Explore what is in `swell-hofx_cf`, try to identify where `experiment.yaml` is located and what is in this YAML file.

# Configuring a Swell Suite

Swell builds an experiment by asking a suite a series of "questions" and resolving each one to a value. Every question is resolved through a layered hierarchy of defaults and overrides, so there are several places a user can intervene depending on how permanent and how targeted the change needs to be. So, it can get complicated. You can review the `experiment.yaml` that got generated for your `hofx_cf` to see these questions and the default values that were assigned to them.

In this training we are going to focus on using **override.yaml**.


## An override file (`-o override.yaml`)

For a repeatable tweak, pass `swell create <suite> -o my_override.yaml`. The override file is a YAML that looks like the final experiment dictionary: any top-level key you list replaces that question's `default_value`. The model-dependent settings go under a nested `models:` block keyed by model component, e.g.:

```YAML
start_cycle_point: '2025-10-10T12:00:00Z'
final_cycle_point: '2025-10-20T00:00:00Z'

model_components:
  - geos_cf

skip_r2d2: false

models:
  geos_cf:
    jedi_build_method: use_existing
    check_for_obs: false
    window_length: PT6H
    window_type: 3D

    # Must match the background ingest override above.
    background_experiment: geos_cf_oper
    background_time_offset: PT9H
    horizontal_resolution: c360
    vertical_resolution: 72
    npx: 361
    npy: 361

    # Match the observations ingested by override_obs.yaml.
    observations:
      - tempo_no2_tropo

    observation_providers:
      - tempo_no2_tropo: nasa_v4
```

To keep track of the overridden values we have started storing them on GitHub swell-config repositor: https://github.com/GEOS-ESM/swell-config


### Editing suite_config.py
In case you need to make a change to the default values you can edit the relevant `QuestionList` in `src/swell/suites/<suite>/suite_config.py`. Each entry (e.g. `ingest_obs_cf`) defines the model-independent questions plus per-model blocks (`geos_cf=[...]`) using the `QuestionDefaults` (`qd`) and `SuiteQuestions` (`sq`) helpers. But in this case, you are changing the Swell code base which may result in diviation from specific tags of this repository.

### Editing the generated experiment directly for debugging
Finally, once `swell create` has produced the experiment directory, the resulting `experiment.yaml` and `flow.cylc` are plain files. For a one-off manual adjustment before launching, you can edit these directly — though for anything you'll want to reproduce, capturing the change as an `override` file or in `suite_config.py` is preferable.
